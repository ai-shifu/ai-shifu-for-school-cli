## MarkdownFlow 运行语义

代码围栏中的内容在 MarkdownFlow 解析前受保护，围栏中的交互标记作为代码展示。HTML 注释不参与授课执行。不要为了布局给独立控件、确定性标记、围栏或图片行添加列表前缀或额外缩进。

## 控件

| 写法 | 效果 |
| --- | --- |
| `?[继续]` | 单个行动按钮 |
| `?[%{{选择一个答案。}} 选项甲 \| 选项乙]` | 单选 |
| `?[%{{哪些情况符合？}} 选项甲 \|\| 选项乙]` | 多选 |
| `?[%{{请说明理由。}} ...写出你的理由]` | 文本输入 |
| `?[%{{选择一个方法。}} 方法甲 \| ...其他方法]` | 单选加文本输入 |
| `?[%{{选择适用的方法。}} 方法甲 \|\| ...其他方法]` | 多选加文本输入 |

第一处分隔符决定单选或多选，`...` 紧接输入提示。`%{{完整问题或任务}}` 是问题前缀，不能填程序键或答案。`?[生成选项]` 只是文字为“生成选项”的按钮，不会请求动态生成。

需要动态选项时，在控件外用自然语言说明使用什么上下文、让学习者决定什么、选项限制和回答方式，并要求发起真实交互、等实际答案后反馈。其正确执行取决于授课引擎，静态文件检查不能证明已实现。

## 记忆与分支

引擎自动记录学习者在课程内的实际输入。自然描述需要使用哪段相关记忆、如何影响讲解；相关信息缺失时用已写明的中性退路，不编造回答，不用旧答案代替等待中的新答案。

MarkdownFlow 没有解析器级 if、循环、布尔表达式或分支图。用自然语言写清不同答案对应的反馈和后续动作，需要再次回答时重新发起互动并等待。

## 确定性输出

完整单行使用 `===需要固定展示的内容===`；多行使用独立成行且配对的标记：

```markdown
!===
第一段需要固定展示的内容。

第二段需要固定展示的内容。
!===
```

行内 `===文字===` 保留该位置的内容，周围仍可生成。存在输出语言转换时，确定性内容也可能按运行规则翻译，不能把标记当作禁止翻译的保证。精确保留的源代码语言、数值、顺序、URL 和表格仍需在写完后逐项核对。
